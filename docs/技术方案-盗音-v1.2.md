## 一、项目定位与目标

### 1.1 项目定位

盗音是一款聚焦多平台音乐搜索、在线试听与高质量下载的轻量化工具，兼容洛雪音源脚本生态，支持歌单批量导入与媒体元数据自动整理。本次面向飞牛操作系统（fnOS）打造纯原生应用版本，彻底剥离 Docker 容器层，实现与 fnOS 系统能力的深度融合，为飞牛 NAS 用户提供更低资源开销、更高系统集成度的音乐下载解决方案。

### 1.2 核心方向

- **彻底去容器化**：全量删除 Docker 镜像构建、容器编排相关的所有配置与脚本，应用直接运行于 fnOS 原生 Node.js 运行时（`install_dep_apps=nodejs_v22` 运行时包），消除容器虚拟化带来的性能损耗与运维复杂度。
- **原生系统适配**：严格遵循 fnOS 应用开发规范（manifest / cmd 生命周期脚本 / config 权限与资源 / wizard 向导 / fnpack 打包 / 统一网关 / 开放 API），完全符合 FPK 打包标准。
- **核心能力对齐**：完整保留搜索、试听、下载调度、歌单导入、元数据处理、音源管理等功能，技术路线与上游觅音（qwex888/miyin）保持对齐。
- **生态深度打通**：原生对接飞牛统一网关（/app/daoyin）、应用共享授权目录（`trim.file.sharedAccess`）、系统媒体库目录，与知音音乐库等 fnOS 生态应用实现「下载即入库」的弱联动。

## 二、整体技术架构

### 2.1 技术栈选型

单仓库全栈 JavaScript/TypeScript 技术体系，运行于 fnOS 提供的 Node.js v22 运行时包：

- **框架**：**Nuxt 4**（`compatibilityVersion: 4`）+ Vue 3 + TypeScript。`app/`（前端）、`server/`（Nitro 服务端）、`shared/`（前后端共享代码）、`tests/`（vitest 单测）统一管理。
- **服务端**：Nitro（`preset: node-server`，esbuild target node20），单进程同时提供 REST API、SSE 与前端静态托管；`server/api/**` 文件路由、`server/services/**` 业务服务、`server/utils/**` 工具。
- **前端**：Vue 3 SPA 页面（搜索/试听/队列/歌单/音源/设置/登录），`@trimjs/web-app`（飞牛 UI 与 SDK）、`@tanstack/vue-virtual`（虚拟滚动）、`qrc-decoder`（QQ QRC 解密）、`fflate`（音源 zip 包）、`zod`（校验）。
- **数据层**：**better-sqlite3@13+**（WAL 模式）。npm 包自带 `prebuilds/linux-x64.node` 与 `linux-arm64.node`，运行时按 CPU 自动加载，一份 `platform=all` 胖包通吃 x86/ARM。
- **运行时**：manifest 声明 `install_dep_apps=nodejs_v22`，脚本中 `export PATH=/var/apps/nodejs_v22/target/bin:$PATH`。
- **元数据**：**ffmpeg** 写入（封面 JPEG 压缩内嵌、标签、内嵌歌词）；系统无 ffmpeg 时跳过写入不影响下载。
- **打包分发**：fnOS 官方 `fnpack`（v1.2.3）生成单 FPK 胖包；统一网关访问 `/app/daoyin`。

### 2.2 模块结构设计

四层扁平化架构映射到单仓库目录：

1. **系统适配层**（`server/utils/fnosEnv.ts`、`fnosOpenApi.ts`、`downloadDir.ts`、`paths.ts`、`runtimeEnv.ts`）
   对接 fnOS 原生能力：`TRIM_*` 环境变量、`$TRIM_PKGETC/miyin.env` 配置注入、`$TRIM_PKGVAR` 数据目录、开放 API（`/var/run/trim_open_gateway_apiscope.socket` + `TRIM_API_TOKEN`）、共享目录与授权路径解析。

2. **核心引擎层**（`server/utils` 与 `server/services` 基础组件）
   音源脚本沙箱（`sourceRuntime.ts`）、多源取链（`musicUrlResolve.ts`）、下载 worker（`downloadQueue.ts`）、平台搜索适配（`platformSearch.ts`）、元数据/歌词（`metadataService.ts`、`lyricService.ts`）、音频校验（`audioSniff.ts`、`audioPreview.ts`）。

3. **业务服务层**（`server/api/**` + `server/services/**`）
   音源管理（`sourceRegistry/sourceImport/sourceProbe/sourceBundle`）、搜索、下载队列、歌单解析（`playlistService`、`trackMatcher`）、设置（`settingsService`）、更新检测（`appUpdate`）、FNOS 目录授权（`fnosDirAuth`）。

4. **前端交互层**（`app/**`）
   搜索试听、下载队列监控、歌单导入、音源管理、系统设置、登录、飞牛授权回调页；SSE 实时推送任务进度；KeepAlive 页面会话管理。

### 2.3 原生运行机制

- **启动流程**：fnOS 应用中心调用 `cmd/main start`。脚本先 `export PATH=/var/apps/nodejs_v22/target/bin:$PATH`，从 `lib_config.sh` 加载 `$TRIM_PKGETC/miyin.env`（AUTH_TOKEN/SESSION_SECRET/DOWNLOAD_MODE/CUSTOM_DOWNLOAD_DIR），解析 `TRIM_DATA_SHARE_PATHS` 得到数据目录与默认下载目录，注入 `NUXT_*` 别名与 `TRIM_*` 透传，后台拉起 `node start.mjs`（Nitro），记录 PID 到 `$TRIM_PKGVAR/app.pid`。
- **进程控制**：`cmd/main` 实现 `start`/`stop`/`status`（退出码 0/1/3）。stop 先 `kill -TERM` 等待最多 15s 再 `kill -KILL`；status 以 PID `kill -0` 探测。`server-entry.mjs` 统一处理 SIGINT/SIGTERM 清理 socket 退出。
- **网络访问（统一网关）**：`micro_app=true`，manifest **不声明 `service_port`**，无对外 Web 端口。用户经 `https://<NAS>/app/daoyin`（或飞牛桌面 iframe）访问。`server-entry.mjs` 启动 Nitro 监听本机 `127.0.0.1:18980`，再用 node http server 监听 `$TRIM_APPDEST/app.sock` 反代到该端口（网关请求自带 NAS 登录态校验）。18980 仅本机内部使用。若未来需要 `http://IP:port` 直连，需另行声明 `service_port`（与网关模式二选一或共存）。
- **权限管控**：`config/privilege` 采用 `run-as=package` 专用应用用户最小权限；下载目录通过共享目录（`config/resource` data-share）或开放 API 授权自定义路径，应用中心可管理授权范围。

## 三、核心功能模块实现

### 3.1 音源脚本管理与沙箱运行

- **生态兼容**：兼容洛雪音源 JS 脚本规范（`lx` 全局对象 + 事件钩子）。脚本通过 `lx.send('inited', {sources})` 声明支持平台与音质表，通过 `lx.on('request', ...)` 处理 `musicUrl` 动作取直链；解析脚本头 `@name/@version/@description` 等元数据。
- **沙箱运行**：`node:vm` 单进程沙箱（详见 §5.1），内置超时、定时器上限、受限 require、熔断机制，单脚本死循环/异常/网络抖动不影响主进程。
- **批量管理**：导入（单文件/批量目录/完整 zip 包）、检测（探针曲目试取链，按 DNS 失败/API 停服/Key 失效/404/500/限流/IP 封禁/脚本需升级分类提示）、一键停用失效、清理；URL 精确去重，同名自动追加 `(2)`。

### 3.2 多平台音乐聚合搜索

- **服务端平台适配**：内置 wy/kw/kg/tx 四平台搜索适配器，直接调用平台公开搜索接口；支持伪 JSON（单引号）、JSONP、`try{var jsondata=...}` 包装解析（`parseLooseJson`）；搜索结果统一归一化为标准结构（标题/歌手/专辑/时长/封面/音质表/`musicInfo`），60s 内存缓存。
- **取链分工**：**洛雪脚本仅用于取直链**（`getMusicUrl`），平台搜索由服务端适配器完成。搜索与取链解耦，脚本失效不影响搜索可用性。
- **多源轮询**：取链时「先按音质档位、再轮询全部音源」，单源失败自动切换；按平台 Tab 展示搜索结果。
- **在线试听**：`/api/preview` 返回音源试听直链，前端播放器直连播放，服务端不中转音频流。

### 3.3 智能下载队列调度

- **队列状态机**：queued / running / completed / failed / cancelled（`downloadState.ts`）；全流程可视化管理，支持重试、取消、删除（可选删本地文件）、批量操作、**换音质**（仅本任务，不改全局默认）、**换源**（指定或同平台轮换）。
- **音质策略**：`QUALITY_LADDER = ['flac24bit','flac','320k','192k','128k']`。「最高可用」按档位从高到低降级、每档轮询全部音源；「固定音质」该档试遍全部音源失败即停，不降级。任务可指定首选音源（仍会轮询其余源）。
- **worker 调度**：Nitro 插件 `download-worker.ts` 启动单进程调度循环（8s tick），并发数可配（默认 1）；任务启动间隔与下载间隔限流，错开取链与连续下载以减轻音源批量风控。
- **质量防护**：试听片段检测（试听 URL 特征、绝对时长、按期望时长对比、`minFullTrackBytes` 按时长×音质最小字节）；下载后用魔数纠正扩展名（`audioSniff`），避免「标称 flac 实为 mp3」。
- **进度推送**：SSE（`/api/downloads/events`）实时推送任务状态与进度。

### 3.4 歌单解析与批量下载

- **多平台歌单**：支持 **wy / tx / kg** 三平台歌单链接解析（`playlistService`），自动提取歌曲名称、歌手、专辑、时长等。
- **精准匹配**：`trackMatcher` 基于歌曲维度信息匹配音源资源，低置信度结果弹出确认弹窗（`MatchConfirmDialog`），避免下载错内容。
- **批量入队**：歌单内多选批量加入队列（`playlist/enqueue`），音质跟随页内选择（默认读设置默认音质）；入队结果弹窗可一键跳转队列。
- **歌词补充**：解析歌单时各平台尽量合并双语歌词（QQ 优先旧 Base64 接口，失败走 PlayLyricInfo + QRC 解密兜底；酷狗 KRC 翻译轨；咪咕 lrc/trc）。

### 3.5 媒体元数据自动补全

- **标签写入（ffmpeg）**：下载完成后用 ffmpeg 写入 title/artist/album/track/disc/date/genre/comment（含 `source=平台`、`quality=`、`id=` 溯源）与内嵌歌词；mp3 用 `-id3v2_version 3`，FLAC 写入后校验 PICTURE block。
- **封面处理**：封面 URL 下载（魔数校验防 HTML）→ 统一压缩为 ≤1000px JPEG → 内嵌（mp3/m4a/flac/ogg）；容器与编码不一致时不嵌封面避免失败。
- **歌词模式**：外挂 `.lrc` 文件与内嵌两种模式；支持 QQ QRC 解密、酷狗 KRC 解码（`krcDecode.ts`）。
- **文件命名**：命名模板支持 `{artist}/{title}/{album}/{platform}/{quality}/{id}/{track}` 占位符，非法字符清洗；下载后按魔数纠正扩展名；同名冲突处理。
- **降级策略**：无 ffmpeg 时跳过元数据/封面/内嵌歌词写入（记录警告），不影响下载任务完成。

### 3.6 鉴权与系统配置

- **灵活访问控制**：`AUTH_TOKEN` 为空 = 开放模式（无登录页，API 免鉴权）；非空则启用登录（`/api/auth/login` 换取 Bearer 会话令牌，`SESSION_SECRET` 签名）。**优先读进程环境变量**（`AUTH_TOKEN`/`SESSION_SECRET` 及 `NUXT_*` 别名），回退 Nuxt runtimeConfig；`SESSION_SECRET` 安装时自动生成、配置变更时保留。
- **可视化配置面板**：设置页支持下载目录（默认共享/自定义+一键授权）、音质策略、默认并发、歌词开关与模式、命名模板、任务/下载间隔、更新检查等，修改即写 `miyin.env` 并提示重启。
- **版本更新检测**：启动后请求 GitHub Release 附带的 `latest.json`（`/api/app/update-check`），`compareSemver` 对比版本，有新版本时设置页红点 + 更新日志弹窗（`UpdateChangelogDialog`）。

## 四、FNOS 系统原生适配方案

### 4.1 标准文件路径适配

严格遵循 fnOS 应用目录规范，**不硬编码路径**，全部通过官方环境变量定位。

| 用途 | 原 Docker 容器路径 | fnOS 原生机制 | 说明 |
|------|--------------------|---------------|------|
| 应用配置 | /data | `$TRIM_PKGETC/miyin.env`（`/var/apps/daoyin/etc` → `/vol{n}/@appconf/daoyin`） | AUTH_TOKEN/SESSION_SECRET/DOWNLOAD_MODE/CUSTOM_DOWNLOAD_DIR，`cmd/main` 与 `lib_config.sh` 读写，0600 权限 |
| 运行数据（SQLite、音源） | /data | `$TRIM_PKGVAR/data`（`/var/apps/daoyin/var` → `/vol{n}/@appdata/daoyin`） | `miyin.sqlite`（WAL）、`sources/*.js`、`downloads/` 兜底目录；卸载时可选清除 |
| 运行日志 | 容器标准输出 | `$TRIM_PKGVAR/app.log` | `cmd/main` 追加写 |
| 临时文件 | 容器内 /tmp | 系统 `/tmp` | ffmpeg 元数据处理临时目录 |
| 默认下载目录 | /downloads | `config/resource` 共享目录（`daoyin/downloads`，经 `TRIM_DATA_SHARE_PATHS` 解析） | 共享目录对系统其他用户可见，媒体库可直接扫描 |
| 自定义下载目录 | — | 用户授权路径（开放 API `trim.file.sharedAccess`） | 设置页一键授权，`DOWNLOAD_MODE=custom` 时生效 |
| 网关 Socket | — | `$TRIM_APPDEST/app.sock` | `server-entry.mjs` 反代到本机 18980 |

### 4.2 系统能力深度集成

1. **统一网关（主通道）**
   `micro_app=true`，`app/ui/config` 声明 `gatewayPrefix=/app/daoyin` 与 `gatewaySocket=app.sock`；`server-entry.mjs` 实现「Nitro 本机端口 + Unix Socket 反代」，网关路径下请求自带 NAS 登录态校验并转发 `X-Trim-Userid` / `X-Trim-Isadmin` / `X-Trim-Username`。无对外独立端口。

2. **开放 API / 应用共享授权**
   通过 `TRIM_API_TOKEN` 调用飞牛开放 API（`/var/run/trim_open_gateway_apiscope.socket`，`POST /api/v1/trimapp`）：`trim.file.getSharedAccessibleFolders` 查询共享授权目录；结合 `@trimjs/web-app` SDK 实现设置页「选择并授权目录 / 授权当前路径」，授权结果写入 `miyin.env` 并提示重启。`manifest` 的 `api-scope` 需含 `trim.file.sharedAccess`，系统要求 `os_min_version=1.2.0401`。

3. **应用中心全生命周期管理**
   安装/升级/卸载/配置向导齐备；数据存放于 `$TRIM_PKGVAR` 与程序目录隔离，升级保留；卸载向导询问保留或删除配置与数据（删除不含已下载音乐）。

4. **系统媒体库联动**
   下载目录默认指向共享目录或用户授权的音乐库路径，落盘即被媒体库/知音音乐库增量扫描，实现「下载即入库」。当前未发现媒体库索引级 API，采用文件系统目录级联动；与知音为弱联动（仅对齐下载目录）。

5. **下载管理中心对接**
   【待验证】官方开发者文档未见下载管理中心公开 API，暂以应用内队列管理为主（并发、间隔、限速由应用自身实现）。

## 五、关键技术设计

### 5.1 音源脚本沙箱执行器（对齐 sourceRuntime.ts）

**目标**：执行用户导入的洛雪系 JS 音源脚本，隔离死循环、异常、定时器滥用与恶意模块加载，同时提供脚本必需的网络与加密能力。

- **沙箱模型**：单进程 `node:vm`。`new Script(code, {filename})` + `createContext(sandbox)` + `runInContext(context, {timeout, breakOnSigint})` 同步执行脚本主体。
- **注入 `globalThis.lx`**（洛雪兼容 API）：
  - `lx.utils.buffer`（from / bufToString）、`lx.utils.crypto`（aesEncrypt / rsaEncrypt / randomBytes / md5）、`lx.utils.zlib`（inflate / deflate）；
  - `lx.request(url, options, callback)`：同时支持 callback 与 Promise，15s 超时、响应体 8MB 上限、JSON 自动解析；
  - `lx.on('request', fn)` 注册取链处理器、`lx.send('inited', {sources})` 上报平台与音质表、`lx.send('updateAlert', ...)`；
  - `lx.env='desktop'`、`lx.version='2.0.0'`（对齐洛雪桌面端）、`lx.currentScriptInfo`（脚本头元数据）。
- **受限 require**：白名单仅 crypto/buffer/url；黑名单 fs、child_process、os、net、dgram、cluster、worker_threads、vm 等，其余一律拒绝（`createRestrictedRequire`）。
- **资源与超时**：加载超时 5s、init 等待 10s、取链超时 20s、定时器上限 32（超限即清理并报错）、脚本文件 2MB 上限。
- **缓存与熔断**：按「路径 + mtime」缓存 handle（5min TTL），`dispose()` 清理定时器；连续失败 3 次进入 60s 熔断窗口（`failCircuit`），避免坏脚本反复拖垮队列。
- **异常降级**：`unhandledRejection` 临时接管（`acquireSourceRejectionGuard`），把脚本未 catch 的网络错误/空值访问降为 warn，避免 Nuxt 打出大量 `[unhandledRejection]`；错误分类 `isBenignSourceNetworkError`（DNS/连接/超时等可降级）。
- **隔离边界说明**：`node:vm` 提供**功能隔离**与运行超时，并非安全沙箱边界；方案不再采用 worker_threads（真实实现为单进程 vm），并明确将其视为「防呆」而非「防恶意」。
- **检测探针**：检测/导入时用固定探针曲目调用 `getMusicUrl`，失败按 DNS 失败、API 停服、Key 失效、404/500、限流、IP 封禁、脚本需升级等给出针对性 `last_error`。

### 5.2 数据持久化设计（对齐 db.ts / paths.ts）

- **数据库**：`better-sqlite3`，`journal_mode=WAL`，路径 `$DATA_DIR/miyin.sqlite`。
- **表结构**：
  - `settings(key, value)`：应用配置；
  - `sources(id, name, url, mirror_url, local_path, enabled, status, platforms, last_checked_at, last_error, created_at, updated_at)`：音源注册表；
  - `download_tasks(id, title, artist, album, platform, source_id, quality, status, progress, file_path, lyric_path, error, attempts, external_id, match_method, match_score, batch_id, playlist_url, music_info_json, file_size, created_at, updated_at)`：下载任务。
- **迁移机制**：`migrateSchema` 通过 `PRAGMA table_info` 检查列并 `ALTER TABLE` 增量补列（如 `file_size`），保证升级兼容。
- **目录**：`$DATA_DIR/sources/*.js`（音源脚本缓存），`$DATA_DIR/downloads/`（共享目录兜底）。
- 采用 better-sqlite3 而非纯 JS 方案的理由：真实实现验证了双架构 prebuild 胖包可行，SQLite 提供事务、索引与并发安全，WAL 兼顾崩溃恢复。

### 5.4 下载调度与可靠性设计（对齐 downloadQueue.ts）

- **worker 循环**：Nitro 插件启动 `startDownloadWorker()`；`tickWorker` 按 `concurrency`（默认 1）串行取 queued 任务（CAS 抢占防止并发重复），`processTask` 单任务处理，`finally` 中递减并 `kickWorker`；兜底 8s 定时 tick。无独立线程/进程。
- **任务流程**：校验下载目录可写（写探针）→ `resolveMusicUrl`（先档位后轮询）→ 试听 URL 检测 → 按命名模板与音质猜测扩展名 → `fetch` + `Readable.fromWeb` + `pipeline` 写文件（进度按 content-length，无则估算）→ 试听片段检测（时长对比）→ 魔数扩展名纠正 → 拉歌词（可选）→ ffmpeg 写元数据（可选）→ 标记完成。
- **失败策略**（`nextStatusAfterFailure` + `isRetryableError`）：
  - 重试性错误（网络/HTTP_RETRY/GET_URL_FAILED）在 `maxAttempts` 内重试；highest 自动换源轮询，固定音质失败即停；
  - 权限类错误（EACCES/EPERM/EROFS）与试听片段不自动重试，提示原因由用户换源/换音质；
  - 取消竞态：取消后已下载文件删除。
- **限流**：`downloadIntervals`（任务启动间隔、下载间隔）错开取链与连续下载，减轻音源批量风控。
- **试听片段防护**（`audioPreview`）：`isLikelyPreviewUrl`（URL 特征）、`expectedDurationFromMusicInfo`、`isLikelyPreviewClip`（实际时长显著小于期望）、`isLikelyPreviewByAbsoluteDuration`（兜底固定试听时长）、`minFullTrackBytes`（期望时长≥90s 时按时长×音质计算最小字节数，下载头即校验 content-length）。
- **说明**：当前路线为**失败整文件重下**，不做 Range 断点续传（真实实现选择）；如需续传可在后续迭代引入。

### 5.5 元数据写入流水线（对齐 metadataService.ts / lyricService.ts / audioSniff.ts）

- **ffmpeg 依赖**：`install_init` 检测 ffmpeg（缺失仅警告）；`writeAudioMetadata` 无 ffmpeg 时返回「跳过」不阻断下载。
- **流程**：封面 URL 下载（魔数校验防 HTML，>12MB 拒绝）→ `prepareCoverJpeg` 压缩为 ≤1000px JPEG → ffmpeg `-map 0:a:0 -map 1:0 -c:a copy -c:v mjpeg -disposition:v:0 attached_pic` 内嵌；仅当容器与嗅探编码一致时嵌封面。
- **标签**：title/artist/album/track/disc/date/genre/comment（`source=平台 | quality=… | id=…`）/lyrics（内嵌歌词）；mp3 追加 `-id3v2_version 3`。
- **格式兼容**：mp3（ID3v2.3）、flac（写后校验 `METADATA_BLOCK_PICTURE`）、m4a、ogg；扩展名以魔数（`audioSniff`）为准。
- **歌词**：`lyricService` 按平台获取（QQ 双语：旧 Base64 接口优先，失败 PlayLyricInfo + QRC 解密；酷狗 KRC 翻译轨 `krcDecode`；咪咕 lrc/trc）；内嵌或外挂 `.lrc`。
- **原子替换**：ffmpeg 输出到临时文件 → 原文件备份 → rename 替换 → 失败回滚，成功删除备份。
- **命名模板**：`{artist}/{title}/{album}/{platform}/{quality}/{id}/{track}`，非法字符替换为 `_`（`sanitizeFilename`）。

### 5.6 鉴权与安全设计（对齐 auth.ts / authMode.ts / fnosEnv.ts）

- **鉴权模式**：`AUTH_TOKEN` 空 = 开放模式；非空 = Bearer 会话（登录换取令牌，`SESSION_SECRET` 签名校验）。`server/middleware/auth.ts` 全局校验，`app/middleware/auth.global.ts` 前端路由守卫。
- **配置注入顺序**：进程环境变量（`AUTH_TOKEN`/`SESSION_SECRET`/`DATA_DIR`/`DOWNLOAD_DIR`）优先，回退 Nuxt runtimeConfig（`NUXT_*`）；`runtimeEnv.ts` 统一封装（生产必须以进程环境为准，避免 Nuxt 构建时求值问题）。
- **路径安全**：下载目录写探针（`ensureDownloadDirWritable`：mkdir + `accessSync(W_OK)` + 写临时文件探测，识别 ENOSPC/EACCES）；自定义目录必须绝对路径（`resolve` 校验）；文件名清洗防路径注入。
- **最小权限**：`run-as=package` 专用用户；沙箱受限 require + 超时；开放 API 仅用 `TRIM_API_TOKEN` 调必要的 `trim.file.*` 接口。
- **合规**：不内置任何平台私有接口/加解密绕过/付费内容解锁逻辑；搜索走平台公开接口，取链由用户脚本承担；公网部署建议设置口令。

### 6.2 生产构建与打包

前置依赖：安装飞牛官方打包工具 `fnpack`（v1.2.3，按平台从官方下载）与 `nodejs_v22` 运行时包。

```bash
# 1. 生产构建（Nuxt 4 / Nitro node-server；网关 baseURL）
NUXT_APP_BASE_URL=/app/daoyin/ GATEWAY_PREFIX=/app/daoyin/ pnpm build

# 2. 打 FPK 胖包（脚本内含 staging、server 独立 npm install、prebuilds 校验、fnpack build）
pnpm build:fpk
#    CI：MIYIN_VERSION=1.0.0 REQUIRE_FNPACK=1 ./packaging/fnos/scripts/build-fpk.sh
```

发布流程（GitHub Actions，推送 tag `v*`）：测试与构建 → Docker 多架构镜像（可选）→ fnpack 打 **x86+ARM 胖包** `.fpk` → 生成 `latest.json` 附到 GitHub Release → 上传 `daoyin-v*.fpk`。本地无 fnpack 时脚本仅准备应用文件后退出 0（`REQUIRE_FNPACK=1` 强制）。

### 6.3 安装与升级

- **本地安装**：飞牛应用中心「本地安装」上传 `.fpk`。安装向导收集访问口令与下载目录；`install_init` 校验 nodejs_v22 运行时。
- **应用商店安装**：上架后直接搜索一键安装。
- **版本升级**：应用内检测更新（latest.json）或应用中心手动更新；`upgrade_init/callback` 做兼容检查；数据存 `$TRIM_PKGVAR` 升级保留。
- **开发期测试**：`appcenter-cli` 在测试设备安装本地包、管理应用、查看日志。

## 七、价值与注意事项

### 7.1 核心优势

1. **更低资源开销**：移除 Docker 层，单进程 Node 服务 + SQLite WAL，适合低功耗 NAS 长期运行。
2. **更高系统集成度**：统一网关（/app/daoyin）、开放 API 目录授权、共享目录、应用中心生命周期全打通。
3. **更简易的运维**：应用中心一键安装/升级/卸载，向导化配置，卸载可选保留数据。
4. **更平滑的迁移**：功能与技术路线与上游觅音对齐，用户可无缝迁移。

### 7.2 合规与使用说明

- 项目仅提供音乐搜索与下载工具能力，不内置、不存储任何受版权保护的音频、歌词、封面等内容。
- 搜索经由平台公开接口的服务端适配，直链获取由用户自行导入的音源脚本承担；不内置平台私有接口、加密绕过或付费内容解锁逻辑。
- 音源脚本由用户自行从互联网获取并导入，使用请遵守当地法律法规及各平台服务条款。
- 公网部署时强烈建议设置访问口令（AUTH_TOKEN），避免未授权访问与滥用。
